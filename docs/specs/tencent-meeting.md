# 腾讯会议动态区域与 MA 编排

状态：实现规格；产品边界已于 2026-10-19 确认。最终验收与 issue 关闭由用户完成。

## Problem Statement

用户需要在个性化新标签页查看今日会议安排，以及最近七天已结束会议的已有摘要。当前页面由一次性 MA session 生成；session 清理后仍需刷新会议数据，且必须保留用户自定义 prompt 决定的布局与样式。腾讯会议凭证过期时需要可信的授权入口，不能让生成页面处理 Token 或执行任意命令。

## Solution

MA 模拟器运行受限的 tmeet 集成服务，负责查询、授权与运行期间的保活。插件提供连接入口，并在自己的可信 UI 中提示用户点击经过验证的授权链接。生成页面必须包含会议区域，但外观由生成模型按用户 prompt 决定。页面通过版本化数据接口接收最新会议快照；刷新不生成新代码、不调用模型，也不依赖旧 session。

## User Stories

1. 作为用户，我希望在新标签页查看北京时间今天的会议安排，以便安排当天工作。
2. 作为用户，我希望查看最近七天截至当前时刻已结束会议的摘要，以便回顾会议。
3. 作为用户，我希望直接看到腾讯会议已有摘要，不让模型另行改写。
4. 作为用户，我希望没有摘要的会议显示“暂无摘要”，并能区分权限不足与查询失败。
5. 作为用户，我希望会议区域服从自定义 prompt 的布局与样式，而不是固定组件。
6. 作为用户，我希望连接成功、打开新标签页和点击刷新时更新会议数据。
7. 作为用户，我希望数据刷新保留页面代码与样式，即使原生成 session 已删除。
8. 作为用户，我希望插件提供明显的连接腾讯会议入口。
9. 作为用户，我希望由可信插件控件展示授权提示，仅在我点击后打开授权页面。
10. 作为用户，我希望凭证能刷新时自动恢复，不因 Access Token 到期重复扫码。
11. 作为用户，我希望授权失败、取消或超时不会卡住首页其他功能。
12. 作为用户，我希望 MA 重启后恢复已启用的保活任务并立即检查凭证。
13. 作为用户，我接受 MA 退出和电脑关闭期间不运行保活任务。
14. 作为用户，我希望网络故障时保留之前成功获取的数据并标注更新时间与过期状态。
15. 作为用户，我希望多个标签页不会重复启动授权进程或造成刷新请求风暴。
16. 作为用户，我希望 Token 不进入生成代码、浏览器存储、模型上下文或普通日志。
17. 作为用户，我希望未安装 CLI、服务不可达或功能不支持时看到可理解的状态。
18. 作为验收人，我希望需求 issue 保持打开，由我决定是否验收和关闭。

## Implementation Decisions

### 范围与职责

- 第一版用于本机、单用户 MA 模拟器和已安装的 tmeet，不实现云端多租户凭证管理。
- MA 集成服务独立于生成 session 生命周期。正常 session 删除不得删除连接配置、授权任务或保活计划。
- MA 执行允许列表内的只读查询及授权命令，不向模型或页面开放 shell，也不接受任意 CLI 参数串。
- 插件负责可信授权控件、请求去重与页面数据传递；生成页面只获取展示所需数据及受限动作。
- 生成模型只需数据契约和示例数据，不需要真实会议摘要或 Token。原文由运行时注入，安全地作为文本展示。
- 影响面包括模拟器服务及路由、agent-core 的生成约定与自定义工具、插件后台与存储、预览运行时与可信 UI、集成测试及文档。既有历史记录构建与非模拟器模式必须继续工作。

### 数据契约（v1）

- MeetingSnapshot：schemaVersion=1、revision、fetchedAt、timezone=Asia/Shanghai、window（todayStart、todayEnd、weekStart、now）、status、meetings、summaries、error（可选）。状态包括 ready、partial、auth_required、unavailable；页面另有本地 loading 状态。
- MeetingItem：id（不透明稳定行键）、meetingCode（可选）、subject、startTime、endTime、status、joinUrl（可选）。UI 不展示内部 meeting_id。
- MeetingSummary：id、meetingCode（可选）、subject、startTime、endTime、summary（原文）、summaryStatus（available、missing、forbidden、error）。周期会议按场次区分，不以会议号作为唯一行键。
- AuthState：status（disconnected、pending、connected、expired、error）、requestId、authorizationUrl、expiresAt（后三项按状态可选）、message（可选）、accountRevision（可选，账号身份的不可读指纹，仅供可信插件区分缓存归属）。Token 永远不在响应中；accountRevision 不传给模型或生成页面。
- 请求必须有有界超时；错误必须区分认证、权限、网络和解析错误。无数据是成功空数组，不能与失败混淆。
- 时间窗口：今天为北京时间当天 00:00 至次日 00:00；近七天为当前时刻减七天至当前时刻，按实际会议结束时间筛选历史会议。日期边界由 MA 统一计算。分页完整处理，资源上限触发时明确 partial，不静默丢失。
- 今日安排包括当天已结束、进行中、待开始的可见会议；跨日会议只要与当天重叠即可展示。账号可见性以 tmeet 返回为准，不承诺获取无权访问的会议。
- 会议列表和摘要可独立失败；不清空另一部分的成功数据。摘要缺失与接口权限不足要有区别。

### MA 接口与生命周期

- 以下为第一版统一接口：GET /v1/integrations/tmeet/status，POST /v1/integrations/tmeet/connect，POST /v1/integrations/tmeet/refresh。
- status 返回 AuthState；connect 返回待授权状态和 CLI 实际生成的链接，或已有连接状态；refresh 返回可信封装 MeetingRefreshResult，包含 snapshot（MeetingSnapshot）和与该次数据读取绑定的 accountRevision。插件依据本次响应的账号标识缓存数据，不复用先前 status 响应的标识；只把 snapshot 下发到生成页面。服务在读取前后检查身份，发生变化则丢弃可能混合账号的数据。运行中重复 connect 复用同一个 requestId。
- MA 使用 tmeet auth login --no-browser 启动受控子进程，保持管道和进程生命周期，读取授权 URL，等待完成并验证状态。禁止 detached 启动；授权超时应回收进程。
- 只有受信 CLI 输出并通过 HTTPS、精确主机与路径校验的授权地址才允许进入插件控件；不能根据模型或页面传入的 URL 导航。
- 授权通知复用 getHistory 风格的结构化请求/结果语义：requestMeetingAuthorization 自定义工具只能请求连接，不接受 URL。插件接收 MA 授权挑战并展示；工具先返回 pending/connected 等明确结果，不把用户点击等待绑定在生成任务上。
- 普通刷新直接访问独立集成服务，不要求启动模型 session。授权完成后插件重新获取数据并推送到所有订阅页面。
- 集成路由不能沿用无限制公开读取本机私有数据的策略：必须验证调用者/凭证与 Origin，拒绝普通网站及伪造 Host；授权链接和凭证不得通过公共 health 接口泄露。
- CLI 不存在、模拟器能力缺失或使用真实 MA 云服务时，会议集成显示 unavailable，不影响原首页生成。

### 保活

- 连接成功后持久化 enabled/nextCheckAt 等最小调度信息；只在 MA 进程运行期间执行。
- 以 CLI 实际到期时间为依据安排检查，在到期边界附近触发受支持的轻量认证查询，复用 CLI 的刷新逻辑。不能假设 auth status 会刷新，也不能把每六小时执行一次 status 当成保活成功。
- 重启恢复时立即检查并重建唯一任务；休眠恢复后补一次检查，避免堆积补跑；正常停止清理计时器与授权进程。
- 后台保活和用户查询共享串行化/合并策略，避免刷新凭证竞态。网络失败有界退避；Refresh Token 失效进入需授权状态，不无限重试。
- 使用系统代理或显式配置的本机 7897 代理，保持 TLS 校验，不全局修改代理配置。

### 页面运行时

- 提供版本化 useMeetingData() 运行时接口，返回 snapshot、loading、error、refresh、connect。该接口只提供数据与动作，不附带固定 UI 或 CSS。
- 生成约定必须要求渲染会议区域、空态、错误态和刷新/连接动作，并能响应数据变化。保持 TSX 产物与运行时版本一并保存，不将数据硬编码为会议 JSX。
- 插件宿主与 Sandpack 预览通过限定消息类型、schema 校验、当前 iframe/source 校验及实例通道标识通信。只在当前页面握手完成后下发数据；拒绝无关 iframe、过期实例、伪造消息和旧响应覆盖新数据。
- 如果 iframe origin 为 opaque，不能仅以 origin 字符串作为身份依据；必须验证实际窗口绑定与独立通道。不得把 API key、Token 或授权 URL 下发到生成页面。
- 会议内容作为不可信文本渲染，不能执行其中 HTML、脚本或指令。外链验证协议；授权只经插件可信 UI。
- 初次连接成功、新标签页打开、手动刷新触发数据获取；后台服务合并并发请求。保留最后成功快照及更新时间，失败时明确过期。账号变化时清理旧账号缓存。
- 旧页面没有契约时提示需要重建页面，不能对旧 TSX 静默插入固定设计；重建成功后再替换既有页面。

## Testing Decisions

沿用既有模拟器端到端测试入口：真实 SDK、HTTP、事件和存储，替换模型和 CLI 进程边界，以可控时间推进授权/续期。再用真实扩展浏览器测试补足 iframe 与可信控件边界，不逐层 mock 所有函数。

1. 首次生成页面接入数据接口，清理 session 后仍能刷新；刷新不调用模型、不改变已保存代码。
2. 两种不同自定义样式均能渲染从 0 到多场会议的更新，长摘要和移动宽度无溢出。
3. 今日与近七天边界、跨日、周期会议实例、分页、空结果、缺失摘要和权限错误正确区分。
4. 未登录、授权链接产生、用户点击、登录完成、取消/超时、多标签复用、worker 重启后恢复状态。
5. Access Token 过期而 Refresh Token 可用时自动恢复；刷新凭证失效时进入授权提示；status 不刷新时测试仍能发现伪保活。
6. MA 重启恢复、退出停止任务、网络重试与防并发刷新；调度不依赖生成 session。
7. 非信任 Origin/Host、错误凭证、恶意 URL、伪造 iframe 消息、旧响应、摘要中的脚本均被拒绝或作为文本显示。
8. 敏感值不出现在工具结果、浏览器存储、生成文件、模型请求和日志。
9. 原有 history/page scraping 流程、云 MA、不含会议接口的旧页面继续可用。
10. 执行类型检查、既有全量测试、扩展生产构建及桌面/窄屏真实浏览器验证。CLI 真实连通性只做最小只读检查，不登出既有账号来制造测试条件。

## Out of Scope

- 系统后台服务、电脑关闭期间运行、系统计划任务。
- 创建/取消会议、邀请成员、通讯录、录制权限申请、自动上传诊断。
- 模型重新摘要、实时转写、主动改变腾讯会议数据。
- 固定样式会议组件、每次刷新重建页面、保留生成 session 作为业务数据库。
- 多用户云服务、多账号切换 UI、通用任意插件执行框架。
- 自动关闭需求 issue；由用户最终验收关闭。

## Further Notes

- 本规格把用户确认的产品约定转换成可实现的第一版接口；字段和接口命名由并行实现统一维护，不分叉为多套协议。
- 已查阅本地 CLI 技能及源码；真实安装版本的授权输出、摘要返回结构、刷新行为需要实现阶段验证，不把文档示例当作实测结果。
- 若因账号权限无法完成真实摘要验证，必须报告具体限制，仍用脱敏 fixture 验证解析与 UI；不得捏造用户会议数据作为验收证据。
